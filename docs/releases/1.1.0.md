# Memely 1.1.0 — Diseño de cristal ahumado

## Cambio visible

- Interfaz oscura translúcida inspirada en la referencia del usuario.
- Fondo atmosférico en CSS, tarjetas redondeadas y acciones en crema.
- Navegación superior y accesos rápidos laterales en escritorio.
- Nuevo resumen semanal con porcentaje y días calculados desde el último menú.
- Login, perfil, medidas y menús adaptados al mismo sistema visual.
- Adaptación móvil, foco de teclado y respeto por movimiento reducido.

No se agregan fuentes, imágenes remotas, paquetes frontend ni llamadas externas.
El resumen semanal usa datos reales de la API; en ausencia de menú muestra el
estado vacío. Los menús siguen siendo ejemplos sin personalización nutricional.

## Alcance

Archivos de aplicación: index.html, css/styles.css y js/app.js.
Sin cambios en backend, API, modelos, migraciones, dependencias ni esquema.
No se modifica compose.release.yaml ni se publica una imagen automáticamente.

## Comprobaciones realizadas

- Sintaxis de JavaScript válida.
- Pruebas Chromium de registro/login, navegación, formularios, siete días y
  veintiuna comidas, actualización del progreso, recarga y cierre de sesión.
- El progreso se recalcula al marcar comidas y al eliminar el último plan.
- Sin desbordamiento horizontal en pantallas de 320, 390, 768, 1024 y 1440 px.
- Capturas revisadas de escritorio y móvil.

Estas pruebas de interfaz usaron una API simulada y no modificaron PostgreSQL.
La prueba con backend real y la suite PostgreSQL deben hacerse antes de publicar.

## Práctica de Docker pendiente

1. Revisar el diseño en el entorno de desarrollo del laboratorio (puerto 8081).
2. Construir la etapa runtime de Dockerfile.alpine como memely-app:1.1.0-alpine.
3. Ejecutar las pruebas Alpine y comprobar el flujo con backend real.
4. Etiquetar y publicar rosellpc/memely-app:1.1.0-alpine.
5. Guardar el digest anterior de compose.release.yaml antes de actualizarlo.
6. Desplegar el digest nuevo, comprobar la apariencia y los datos.
7. Revertir al digest publicado 1.0.1 y finalmente regresar al de 1.1.0.

No se ejecutan downgrades de base de datos en esta práctica: ambos diseños usan
la misma API y el mismo esquema. Conservar el volumen PostgreSQL y un backup.
